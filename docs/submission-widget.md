# Embed a submission entry

The `vulnseal-submission` custom element gives a program website an entry into VulnSeal's private reporting workflow. It displays the public network, contract and program ID, then opens the invitation review in a separate tab. Report authoring, encrypted backup, disclosure exchange and wallet operations run in that VulnSeal workspace. The embedding page has no private-report form, wallet integration, message bridge or return callback.

In the vendor workspace, open Reports and expand **Embed report entry on your website**. Copy **Submission widget embed code** into the intended program website. It contains the module script, a public invitation attribute and an ordinary fallback link. Review the URL before publishing: a localhost URL is only usable on that local machine. Use an HTTPS hosted release directory for a public website, preferably a retained `/releases/<version>/` deployment so the loader and its shared module stay together. Generating code does not publish or deploy it.

The production build emits `assets/submission-widget.js` and its small shared invitation-parser module. The widget loads neither React nor Midnight/WASM/proving assets on the embedding page and makes no API request. Its script tag uses anonymous cross-origin loading and no referrer; its navigation link has `noopener noreferrer` and opens a new tab. The shared parser also backs file/link invitation handling in the main app and is available from `@vulnseal/api/program-invitation`.

The default Caddy host and local production preview allow credential-free cross-origin reads only for the widget module and `program-invitation-*.js`. Custom hosts must serve those files with a JavaScript MIME type and `Access-Control-Allow-Origin: *`; they should not enable credentialed access. The widget entry name is stable, and the supplied Caddy configuration uses `Cache-Control: no-cache`. Keep dependent hashed modules available when retaining an old release.

An `invitation` attribute change revalidates and replaces the displayed destination. Invalid, private-field, credential-bearing or unsupported URL input removes the interactive widget link. No HTML from attributes is evaluated. If JavaScript is disabled or the module cannot load, the ordinary child link remains available; the destination application still requires JavaScript for reporting.

The element uses a shadow tree with static built-in styles. Host pages can customize `--vulnseal-widget-surface`, `--vulnseal-widget-text` and `--vulnseal-widget-accent`, or style `::part(container)`, `::part(title)`, `::part(details)`, `::part(identifier)` and `::part(link)` from their own stylesheet. A host CSP must permit the chosen module origin. If it blocks the built-in inline style, the widget remains functional but the host should style its exposed parts, including wrapping long identifiers. No host CSP is relaxed by the widget.

The host page necessarily knows the public invitation and loads third-party code from the selected release. The widget does not authenticate the program's identity or permission to test; the researcher must confirm those before joining. It transfers no keys or report content back to the host. Native Lace completion through this entry, public TLS hosting and independently audited deployment remain separate release gates.
