# Add a public GitHub release to patch notes

Open a saved report in a vendor workspace and use **Add a public release reference**. Enter its full `https://github.com/owner/repository/releases/tag/<tag>` URL, then click **Look up public release** or press Enter in that input. Review the repository, publication/prerelease status, release ID, tag, commit and publication time. **Append release reference to notes** preserves the current notes and adds the displayed text after a blank line. It does not submit a transaction. Offline vendor workspaces can prepare the notes before reconnecting to the contract.

The existing **Anchor patch** command hashes the entire notes field as UTF-8, including both earlier private text and the appended reference. It does not hash downloaded patch files or prove that the release fixes the report. The normal encrypted backup/autosave gate still applies; each submitted report command's journal captures its notes through the existing pre-wallet checkpoint. Later edits do not rewrite those snapshots. Import alone creates no checkpoint and changes no ledger state.

The client first checks public repository identity, reads GitHub's [release-by-tag metadata](https://docs.github.com/en/rest/releases/releases#get-a-release-by-tag-name), then resolves `tags/<tag>` through the [SHA-only commit endpoint](https://docs.github.com/en/rest/commits/commits#get-a-commit). It uses the tag's reported commit, not the repository HEAD or the release's potentially branch-based `target_commitish`. Only selected release fields are retained. Public release responses may include body/author/asset metadata, but those fields are neither rendered nor appended. Assets, source diffs and repository archives are not fetched.

All three reads share one 15-second application deadline. Repository/release JSON is bounded to 256 KiB each; SHA text is bounded to 128 bytes and must contain a full 40-character SHA-1 identifier. Drafts, inconsistent repository/tag identity, invalid publication dates and unusable responses fail the lookup. Prereleases are explicitly labelled. Only fixed GitHub API paths are used, tag components are encoded, redirects are rejected, and requests omit credentials, authorization, body and referrer. GitHub still sees network/browser connection metadata. No actor secret, disclosure, report identifier or private notes are sent.

Cancelling, changing the URL, switching reports or closing the component aborts the pending lookup and discards late results. Input and preview are transient; appended text is stored through the existing per-report note schema. A notes-size validation failure leaves the previous notes intact and reports the error. The release fields are local working evidence, not a new authenticated backup schema.

GitHub's metadata/tag reads are not atomic. A release or tag can change between reads, and object availability is not guaranteed. The reference does not independently verify Git objects, signatures, asset digests, maintainer ownership, scope membership, test permission or remediation. GitHub App installation, webhooks, private repositories and authenticated source/release provenance remain outside this feature.
