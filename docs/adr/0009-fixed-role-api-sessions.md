# ADR-0009: Fixed-role API sessions and atomic private witnesses

Status: accepted, 2026-09-09.

The low-level API allows callers to install private state separately from invoking a circuit. The experimental browser uses this to switch between two actor secrets. Independent clients need an adapter that retains one actor secret, fixes its role, checks current public subjects, and installs the correct witnesses for each operation.

`RoleSession` is exported from `@vulnseal/api/role-session`. `attach` wraps a deployed/joined API; `join` creates the underlying API using the caller's providers. Each session copies one role, program ID and actor secret into private fields. It exposes no secret getter or role switch, and JSON serialization contains no identity material. A vendor session verifies the program-bound vendor key at attachment and before every transaction. A researcher can submit a new report, and can retest only when its derived researcher key and supplied preimage match the selected ledger record.

The command allowlist separates researcher operations (`submitReport`, `submitRetest`) from vendor operations (`beginTriage`, `acceptReport`, `rejectReport`, `anchorPatch`, `authorizePayout`, `closeReport`). Wrong-role commands fail before private-state installation or transaction invocation. Commands copy caller-owned arrays before awaits, check byte lengths and tiers, and validate current ledger membership, legal workflow stage and subject bindings. Retests must name the current patch. Duplicate submissions are rejected on the current record. Contract assertions remain the authoritative enforcement, including changes racing with proof generation.

`VulnSealApi.withPrivateState` serializes witness installation plus the provided operation using a queue keyed by the private-state provider object. Different API instances sharing that provider use the same queue, including different contract addresses. Failures during installation or invocation release the queue. Inputs are copied before queue acquisition; malformed non-cloneable input cannot leave a stuck queue. Role-session state checks occur inside this operation, so queued work reads fresh state before invoking a circuit.

This queue covers cooperating calls through `withPrivateState`; existing raw `usePrivateState`/circuit calls do not acquire it. Applications must not mix those raw operations concurrently with role sessions on one provider. Separate users should use separate providers, processes/browser contexts and encrypted authority storage. JavaScript role checks are not a security boundary against a process holding both actor secrets. The API does not claim to erase all runtime copies of secrets, authenticate a vendor's civil identity, rotate secrets or persist role authority.

The simulator integration uses two API instances, fixed vendor/researcher sessions and the generated Compact circuits through closure. It verifies which actor witnesses reach each circuit, denied commands, stale subjects, duplicate queues, identity-array mutation and queue recovery. These tests do not generate proofs, sign with Lace or submit network transactions. The browser still uses its combined experimental authority session; independent program invitations, role-specific encrypted recovery and browser transaction flows remain open.
