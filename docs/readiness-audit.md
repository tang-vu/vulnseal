# End-to-end readiness audit

Audit started 2026-09-09 from the current worktree. The goal is a complete, polished project; passing the existing Wave 1 tests alone does not establish that outcome. The September 2 Preprod deployment was independently reverified on September 9: all eight recorded identifiers remain successful and finalized. That recheck is not a new deployment or a production readiness claim.

## Verified implementation improvements

- Browser network mode requires both wallet connection and program deployment. Guided reports cannot silently become network reports.
- Wallet connection/configuration must match the requested network; the SDK network ID is updated on connection, and authorization is rechecked before balancing or submitting. Mobile exposes the wallet control.
- Program form values determine the displayed policy and deployment digests. Severity and private rationale drive the actual acceptance call.
- Vendor and researcher authorization secrets and program identifiers use cryptographic randomness rather than public fixed constants. The combined demo retains both actors; the independent `/#roles` entry keeps one active role per workspace.
- Browser transitions follow contract prerequisites, reject duplicate in-flight actions, expose closure, and retain rejected/failed-retest history.
- Verifier statements describe the actual stage. Transaction identifiers and heights are associated with report events, excluding the deployment transaction. The view explicitly identifies itself as session evidence, not an independent current-state query.
- A failed public-state read after finalization preserves the transaction and offers a read-only retry instead of resubmitting it.
- The ciphertext service publishes complete, flushed files atomically with no overwrite. Concurrent identical uploads are idempotent. Corrupt stored blobs, invalid encodings, missing authentication tags, and storage failures have explicit responses.
- Canonicalization handles Unicode-normalized object keys deterministically, rejects collisions, preserves special object keys, and validates attachment digests and sizes. Decrypted report documents undergo schema normalization before rendering.
- The UI no longer requests external fonts. Production browser journeys are included in CI configuration.
- Private recovery exports password-encrypted session snapshots and restores incomplete drafts or sealed reports. Current network authority/state is checked before restoring; backup history does not become transaction finality evidence. The recovered ciphertext copy permits decryption when storage is unavailable.
- The separate role workspace requests a leave warning for unsaved ownership/reports, private form edits/notes, loaded receiving keys and active operations. Chrome desktop/mobile can cancel closing an unsaved identity; the warning clears after encrypted identity persistence. Working notes and tier selections are now saved per report, and incomplete researcher report drafts persist through encrypted role autosave and file export; only the latest confirmed save is recoverable.

See [validation-report.md](validation-report.md) for executed commands and their results. Mocked wallet tests do not establish that the native Lace integration works end-to-end.

The startup error screen also offers export-only access to encrypted browser copies without loading the Midnight SDK. Downloads preserve the stored encrypted bytes and password; a revision change requires refreshing the catalog. This provides access to persisted role backups during a workspace load failure, but cannot recover unsaved edits or operate when the bootstrap script itself is unavailable.

## Work still required

Optional browser/API ciphertext replication now supports two or three explicit endpoints: all must acknowledge writes, and reads fall back only after enforcing the existing deadline, size/UTF-8 and digest checks. A desktop/mobile drill used two real service instances with separate local data directories, verified both stored envelopes, blocked partial upload completion, rejected corrupt reads and retained the local-copy fallback when all sources failed. This implements client replication across HTTP instances, not a second storage-adapter implementation, automatic historical backfill, cross-region independence, repair or retention/deletion policy. See [replication configuration](cipherstore-replication.md). A backed-up role workspace can now explicitly backfill all saved ciphertext in order, stop remaining uploads, and retry identical envelopes after a partial failure. The increment passed 113 web tests and four two-store browser cases with three saved reports; upload progress is local and has no durable resume cursor.

The combined experimental flow now keeps pending ciphertext and its commitment material before upload. Recovery v3 preserves it without completed-report history; explicit storage retries reuse the same bytes. A conservative flag set before network submission setup blocks retries after uncertainty and survives export/restore. This improves manual recovery but is not a durable per-attempt journal: a crash or an older backup can predate that flag, and native-wallet/report-effect reconciliation remains open. See [ADR-0022](adr/0022-pending-demo-preparation.md).

Independent role preparation now retains the exact encrypted disclosure locally before any upload. Upload requires a saved role backup and can be repeated after offline restoration with identical bytes/address. Initial report submission uploads those saved bytes before entering the contract call; storage failure prevents that call. A real local-service desktop/mobile drill dropped a successful PUT response, restored the encrypted backup in an isolated browser and reuploaded the original envelope. This closes the role preparation/upload-loss gap, while binary attachments, physical off-device recovery and native-wallet uncertainty remain open. See [ADR-0021](adr/0021-prepared-ciphertext-recovery.md).

A fresh isolated Compact `0.31.1 --skip-zk` compilation now confirms that retained metadata, JavaScript/declarations and all eight textual ZKIR circuits match the current source. `release:build` requires this comparison before packaging, and CI is configured to run it with rejection tests. Source maps match except for their directory-dependent root. This closes the unchecked retained-binding/circuit-input freshness gap; fresh key/BZKIR generation, compiler authentication, native-wallet proof execution and remote CI remain separate gates. See [release checks](web-release.md).

A two-backend rollout configuration now retains separate release paths while changing only the root redirect. A local drill used two distinct compiled images, promoted A to B, loaded A's old role-workspace chunk from an already open A page, rolled back and rehashed both artifacts. Backend container identities and the serving origin stayed fixed. This implements local two-release retention and rollback; public ingress/TLS, high availability, retention expiry and cross-schema compatibility remain operator/release work. See [retained web releases](web-rollout.md).

The web build now supports a release subdirectory: relative entrypoints/chunks, directory-relative proving resources and links that preserve the current release path. The HTTP artifact checker accepts a directory base URL. The local two-release drill above verifies retention and switching; expiry, backup-schema compatibility and public ingress remain deployment work.

Role-vault v8 now preserves private working-note/tier snapshots with individual report submission attempts before the encrypted pre-wallet checkpoint. Later edits preserve old snapshots, and encrypted file/browser recovery retains them. The wallet-free inspector excludes this private context from its projection. These snapshots improve per-report history but are neither authenticated circuit arguments nor a cryptographic append-only log; native-wallet recovery and complete reconciled transition history remain open. See [ADR-0020](adr/0020-private-submission-notes.md).

The wallet submission response now has a two-minute deadline after the durable identifier checkpoint. Expiry retains the identifier as an unknown outcome and does not retry; late authorization cannot start a broadcast after expiry, and a late connector result cannot turn the finished call into success. This bounds that application wait, not the actual wallet/network operation, initial connection, proving/balancing or SDK finality polling. Native Lace behavior and semantic retry remain unverified.

The checked web artifact now has a digest-pinned static hosting image and localhost Compose configuration. A local container drill passed full HTTP asset comparison, MIME/cache/security headers, missing-file responses, non-root/read-only execution, captured-state lookup in desktop/mobile browsers and graceful restart. This provides a runnable hosting artifact; public TLS/DNS/ingress, endpoint configuration, monitoring, full CSP validation, rolling-upgrade asset retention and native-wallet verification remain open. See [web hosting](web-hosting.md).

Public lookup, transaction observation and report replay now share a bounded streaming JSON reader with cancellation and strict UTF-8 decoding. Transaction responses allow 1 MiB each and state/replay responses 16 MiB each. Twenty focused tests and eight production desktop/mobile regressions passed. These client input bounds improve robustness against oversized evidence responses without authenticating indexer data or establishing safe retry.

An explicit HTTP release check now compares the local inventory with each served file and the origin homepage, enforcing byte/hash equality, HTTP status, JS/CSS/WASM/HTML MIME types, redirect refusal and bounded downloads. All 62 files and the root page passed through loopback Vite preview; four packaging/HTTP tests passed. The same command can check a chosen HTTPS deployment, but no public host has been validated by this local evidence.

The web release now has a separate packaging gate requiring each proving circuit's prover key, verifier key and binary ZKIR to match local compiler outputs. The production build and read-only manifest check passed for eight circuits and 62 files; synthetic rejection rules are included in CI. This establishes local package completeness, while compiler provenance/freshness, actual hosted asset availability and native-wallet release validation remain open. See [the release guide](web-release.md).

Recovery journals now also offer an explicit worker-based report-effects check: finalized successful transaction observation, bounded predecessor discovery, RPC block checks and shared SDK data-state replay must match the saved program and report. The production worker passed captured-transaction browser tests, while the valid encrypted-backup UI test covers program mismatch and cancellation. Native Lace recovery, intended-argument matching, authenticated history/code and safe-retry decisions remain open; see [the precise scope](transaction-content-investigation.md#browser-recovery-journal-check).

Successful SDK return values are now checkpointed as local finalization claims in encrypted role-vault v6 before follow-up ledger reads. Deployment saves the learned address and receipt together. Storage failure preserves an exportable in-memory vault and does not resubmit. Legacy backups remain readable; absence of a saved receipt still leaves the outcome unknown. This improves durable successful-outcome history, while unknown/failed outcome reconciliation and the crash window before receipt persistence remain open. See [ADR-0018](adr/0018-saved-sdk-finalization.md).

The ciphertext service now has a digest-pinned container image and localhost Compose deployment with persistent storage, non-root execution, read-only root and readiness checks. A real local container drill verified quota handling, writer exclusion, graceful restart and decryption of retained bytes; a separate Compose launch reached healthy readiness. This supplies a deployment artifact and repeatable local evidence, while public hosting/TLS, access controls, image scanning, external monitoring and physical backup drills remain open. See [the operator guide](cipherstore-operations.md#container-deployment).

Transport limits now bound retained connections, incomplete request receipt, header receipt and socket inactivity. Real TCP tests cover continuously trickled data, silent connections, refusal above capacity and successful upload after timed-out input; the Linux container drill also terminates a trickled upload before testing normal persistence. These are process-wide controls, not per-user fairness or a substitute for proxy rate limits and load testing.

No overall completion or production-readiness claim is made. Manual encrypted recovery and independent current-state public lookup are implemented, with native-wallet verification and pending-transaction recovery still open. Next validation priorities are the native Lace multi-profile ceremony and transaction/circuit-bound recovery. Local role isolation, encrypted multi-report ownership, drafts/notes and same-tab workspace switching have implementation and browser evidence; they do not establish those remaining network gates.

Role replay now compares saved v8 decision-note digests for acceptance/rejection and saved severity/reward tiers for acceptance/payout authorization against source-replayed public values, entirely locally. Discrepancies are visible; missing historical snapshots and other circuits are explicitly not compared. This does not establish complete intended-argument reconciliation, terminal history, authenticated backup/chain evidence or safe retry. See [ADR-0023](adr/0023-saved-decision-comparison.md).

For report submission, it also hashes the saved disclosure envelope and compares its digest against the replayed record. This binds the locally retained ciphertext bytes to the observed public content address without uploading the envelope or testing remote retention. Full submission arguments and safe retry remain unverified.

[Raw transaction investigation](transaction-content-investigation.md) now supplies seven captured historical contract transactions with SDK-recomputed hash/identifier checks. The SDK VM also replays the six successful report calls against captured historical states, with full contract data-state equality and changed-report projections. A bounded deployment-to-target WebSocket scan now discovers the predecessor used by a live replay without selecting it from the stored lifecycle list. The browser journal now invokes this conditional replay explicitly. It remains source-trusting, successful single-call evidence; authenticated inclusion, complete intended-argument reconciliation and safe retry remain unimplemented.

## Subsequent recovery and wallet verification

The consolidated run at code revision `87071f8` passed all 230 tests across six workspaces, including 150 web tests in 32 files. The full expanded ordinary browser suite passed all 70 cases, and the separate replication suite passed four cases. All completed without retries. See the latest validation-report section for exact scope; simulator and injected-connector coverage does not establish native Lace compatibility.

Wallet setup, transaction authorization reads and balancing now have bounded waits that do not resume a timed-out caller. ZK artifact downloads have header/body deadlines and byte limits. Native Lace execution and an overall proving/finality deadline remain unverified.

Role-vault v9 retains explicit per-attempt Pass/Fail choices without inferring old ones. Local replay comparison now includes patch commitments and retest note/choice commitments, in addition to ciphertext and decision fields. The retest comparison uses the observed patch; independently saved intended patch, full argument reconstruction, authenticated chain/backup evidence and safe retry remain open. The wallet-free inspector excludes private note and retest context. See [ADR-0023](adr/0023-saved-decision-comparison.md) and [validation evidence](validation-report.md).
