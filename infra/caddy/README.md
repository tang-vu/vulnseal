# Caddy runtime build

The web and rollout Dockerfiles compile Caddy 2.11.4 with Go 1.27.1 from a digest-pinned builder. This module uses Caddy's standard modules and command entry point, following the [upstream custom-build instructions](https://caddyserver.com/docs/build). Both images copy the resulting static binary over the upstream runtime binary. No binding capability is assigned; the service listens on port 8080.

`go.mod` and `go.sum` pin the complete dependency graph. Security updates include cel-go 0.30.0, compress 1.18.7, chi 5.3.0, x/crypto 0.56.0, x/net 0.58.0, x/text 0.41.0 and gRPC 1.83.2. Go module selection can raise transitive minimums; inspect the resulting graph when updating a version. Docker verifies downloaded modules and builds with `-mod=readonly` and `GOTOOLCHAIN=local` so compilation cannot silently select a different toolchain or rewrite the graph.

`apply-cel-compat.sh` backports two `NewCall` argument types from [upstream Caddy's CEL matcher](https://github.com/caddyserver/caddy/blob/master/modules/caddyhttp/celmatcher.go) to accommodate the cel-go 0.29/0.30 API. It checks the SHA-256 of the entire original 2.11.4 source file and requires exactly two replacements. The patch is applied after module checksum verification, inside the disposable builder; this is a modified Caddy build, not an untouched upstream binary. CEL/expression tests run before compilation. When updating Caddy, review whether this backport is still needed instead of merely changing the expected hash.

To update dependencies, use the same pinned Go container with this directory mounted at `/src`, run `go mod tidy` after selecting explicit versions, and review both module files. Build both Dockerfiles, scan each final image archive, and run the static hosting and retained-release rollout drills. A successful build or functional drill alone does not establish absence of known vulnerabilities. Scan evidence and its database timestamp are recorded under `docs/evidence`; repeat scans when the database or any build input changes.

The compiler and module download cache stay in build stages. Client release/compiler artifacts remain independently checked by the existing web packaging gate; this module does not alter Compact sources or proving keys.

The additional CEL/compress/chi updates follow the Go advisories for [CEL native-type field exposure](https://pkg.go.dev/vuln/GO-2026-6094), [S2 dictionary reads](https://pkg.go.dev/vuln/GO-2026-5841), and [Chi RealIP handling](https://pkg.go.dev/vuln/GO-2026-5777). Updating their module versions does not assert that each affected function was reachable through our configuration. See [Go scan precision and evidence](../../docs/go-vulnerability-checks.md), especially the limitations of stripped-binary diagnostics.
